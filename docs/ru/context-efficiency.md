# Token-efficient AGENTS.md и SPEC.md

Файл инструкций — это бюджет внимания, а не документация. Оплачивается каждая строка: она участвует в контексте каждой сессии и конкурирует с задачей. Цель — минимум проверяемых правил, которые нельзя вывести из кода и которые нужны в большинстве сессий.

## Бюджет

| Файл | Цель | Потолок |
|---|---:|---:|
| Глобальный `AGENTS.md` | 25–40 строк / <500 токенов | 60 строк |
| Корневой `AGENTS.md` | 100–200 строк / 1–2k токенов | 200 строк |
| Вложенный `AGENTS.md` | 20–60 строк / <700 токенов | 100 строк |
| `SPEC.md` | 80–150 строк / ≤1,5k слов | 2k слов |
| `ADR` | 30–60 строк / <700 токенов | 100 строк |

`orch_uni_context_lint` применяет один бюджет корня (`max_lines`, по умолчанию 200 строк) и бюджет слов SPEC (`max_words`, по умолчанию 1500 — цель из таблицы; потолок 2k включается через `max_words: 2000`). Цифры по уровням выше — ориентир для автора, а не отдельные лимиты инструмента.

Правило отбора: если строка не проверяема, выводима из кода/линтера или нужна реже половины сессий — удалить либо вынести в ссылку.

## AGENTS.md: 12 правил

1. Команды — в начало: install, build, test, one test, lint, run; с флагами и рабочей директорией.
2. Только невыводимое: флаги, ловушки, порядок слоёв, запреты, версии.
3. Одна инструкция — одна строка, императив, проверяемо.
4. Стиль — линтеру; не пересказывать README и стандарт языка.
5. Явные «Never» и «Ask first»: секреты, `dist/`, prod, миграции, зависимости.
6. Приоритеты — в тексте: что переопределяет что; при конфликте — остановись и спроси.
7. Один источник правды: `AGENTS.md` + симлинк/импорт для `CLAUDE.md`.
8. Ссылки вместо инлайна; инлайнить только то, что нужно всегда.
9. Правило добавлять после повторной ошибки агента, а не «на будущее».
10. Мёртвое правило удалять: это налог на каждый запрос.
11. Стабильное — вверх, даты/ветки/задачи — вниз (prefix cache).
12. Ревьюить файл как код; менять при смене тулинга/CI.

## Шаблон AGENTS.md

```md
# AGENTS.md

## Приоритеты
1. Явное указание пользователя в задаче.
2. SPEC.md активной фичи.
3. Ближайший AGENTS.md.
4. Этот файл.
5. Глобальный AGENTS.md.
При конфликте — остановись и спроси.

## Команды
| Задача | Команда | Примечание |
|---|---|---|
| Установка | `<...>` | `<версия>` |
| Сборка | `<...>` | `<флаг>` |
| Тесты | `<...>` | `<лимит>` |
| Один тест | `<...>` | `<имя>` |
| Линт/типы | `<...>` | |
| Запуск | `<...>` | `<порт>` |

## Границы
- `<path>/` — сгенерировано, не редактировать.
- `<path>/` — вендорное, не редактировать.
- Новые файлы — в `<path>`.

## Конвенции
- <Одно проверяемое правило на строку.>

## Проверка
`<analyze>` → `<lint>` → `<test>`.

## Никогда / сначала спроси
- Никогда: секреты, `dist/`, prod, применённые миграции.
```

## SPEC.md: 12 правил

1. Одна фича — один файл, 1–3 страницы; больше — split через roadmap.
2. Стабильные ID (`R1`, `AC1.1`), не перенумеровывать.
3. Одно требование — одно наблюдаемое поведение.
4. EARS или Given/When/Then — единообразно; MUST/SHOULD/MAY — редко.
5. Никакого HOW: стек, файлы, классы — в plan/design/ADR.
6. Контракты — ссылками, не копиями.
7. Non-goals — 3–7 пунктов.
8. Инварианты — отдельно от acceptance criteria.
9. Таблицы — для AC и трассировки; проза — для контекста.
10. Frontmatter: `status`, `owner`, `version`, `supersedes`; без changelog в теле.
11. Не более трёх открытых вопросов, у каждого owner и дата; `TBD` в других местах запрещён.
12. DoD и метрики — измеримые; «быстрее» без числа не считается.

## Команда /agents-md

1. Определи режим: аудит существующего файла или черновик с нуля.
2. Для аудита: `orch_uni_context_lint` → `context-lint`; покажи SGR и `closing_list`.
3. Для черновика: собери факты и задай не более 8 вопросов; не выдумывай команды и пути.
4. Заполни шаблон; уложись в 150–200 строк.
5. Прогони линтер, покажи diff и открытые вопросы.
6. Канонический файл меняй только после подтверждения; правки — через `fix-runner`.

## Команда /spec

1. Зафиксируй бриф и задай не более 5 уточняющих вопросов.
2. Non-goals, приоритеты и метрики утверждает владелец; не придумывай их.
3. Заполни шаблон: EARS, AC с тестами, инварианты, трассировка, DoD.
4. Прогони `orch_uni_context_lint` и `context-lint`; покажи diff и вопросы.
5. Канонический файл меняй только после подтверждения.

## Ревью

- [ ] `AGENTS.md` ≤200 строк, `SPEC.md` ≤1,5k слов.
- [ ] Каждая строка проверяема.
- [ ] Нет дублей с README/линтером/CI.
- [ ] Приоритеты и границы прописаны.
- [ ] Все относительные ссылки существуют.
- [ ] У каждого R есть AC, у каждого AC есть тест.
- [ ] Non-goals и DoD на месте.
- [ ] Есть baseline на 10–20 задачах.

## Анти-паттерны

| Анти-паттерн | Почему плохо | Что делать |
|---|---|---|
| Автогенерация «на всякий случай» | −0,5…−2% успеха, +20–23% косты | Писать вручную, только высокосигнальное |
| Пересказ README/архитектуры | Дублирование, нулевой эффект | Ссылка на docs |
| Дублирование линтера | Токены на то, что и так проверяется | Линтер/CI |
| Общие фразы («пиши чисто») | Непроверяемо | Императив + пример |
| Противоречия между уровнями | Модель выбирает произвольно | Явные приоритеты |
